# Managed state and UI regression tests

On Windows with .NET 10, run the managed state tests from the repository root:

```powershell
dotnet run --project tests/managed/ManagedStateTests.csproj -c Release -- --output .runtime/qa-managed-results.json
```

The tests use a newly created temporary directory, never the application's saved state, and remove their fixtures on completion. They cover saved-key parsing, bounded reads of oversized records, atomic single-device removal and server-identity retirement, locked-file rollback, settings recovery and localization, plus media snapshots, progress bounds, session identity, and backward-compatible automatic full-screen settings. `ArtworkFlowTests.cs` checks bounded cover-texture generation, spatial structure, opaque blending and the loop seam; `MusicMotionTests.cs` checks density-driven pace, time-based smoothing, invalid samples and reset behavior. `LyricsTests.cs` checks LRC timestamps, offsets, interludes, line and length bounds, active-line lookup, LRCLIB JSON binding and duration-based selection; offline HTTP fixtures also cover fallback, caching, stalled response-body deadlines, failure retry and caller cancellation. They do not access the network or start an AirPlay receiver.

The in-app UI harness sources under `tests/ui/MainWindow.*UiTests.cs` are linked into the app only when `EnableUiTests=true`. Media checks use synthetic state, exercise actual image decoding and window paths, and do not send real playback commands. `MainWindow.ConnectionUiTests.cs` checks authenticated idle connection text independently of metadata revisions, pause and media completion, disconnect and stop, language and tab changes, and startup/PIN/error precedence. The optional strict-boolean `connected` snapshot field is checked by the managed parser tests; actual verified-socket lifecycle is covered by the native protocol tests. Build the UI harness from the repository root with separate output and intermediate directories:

```powershell
dotnet publish src/ClearCast/ClearCast.csproj -c Release -r win-x64 `
  -p:EnableUiTests=true -p:BaseIntermediateOutputPath=../../.runtime/obj-ui/ `
  -p:BaseOutputPath=../../.runtime/bin-ui/ -o .runtime/app-ui
```

Create an empty `clearcast-ui-test-state.marker` in a disposable `CLEARCAST_HOME`, set `CLEARCAST_UI_TEST_RUN=1`, and launch that test executable after other AirPlay receivers have stopped. It writes `ui-test-output/results.json` and controlled-theme PNG files, then exits. Normal builds exclude the UI test source entirely.

Set `CLEARCAST_UI_LYRICS_ONLY=1` for lyrics regression immediately after startup. This mode does not start a receiver or occupy its ports. Offline responses exercise the actual async lookup and presentation path for synced and plain lyrics, their shared typography, the two-line plain-lyrics footer, manual browsing, and duration arriving after or during an initial miss. It then runs the existing lyrics layout, highlighting, blur, full-screen, track-change and open/close checks without changing their visual parameters.

In the same mode, set `CLEARCAST_UI_LYRICS_STRESS=preferences` to isolate the playback settings checks. They cover music/video automatic full-screen transitions, respect for manual exits, lyrics setting/player-button synchronization and persistence, and both settings cards' layout. Floating controls are checked against their preceding windowed width, screen limits and bottom gap, including the owned native window's rounded exclusion and hide/show restoration. Spatially varying synthetic video samples exercise the actual frost image path; bitmap and rendered-background pixels verify visible color variation, changed source pixels and bitmap reuse. Screenshots show mirroring and direct-video controls. Reset, source replacement, hiding and full-screen exit verify image cleanup, while disabled system effects record the material fallback. These checks use no receiver or decoded video and do not establish real-frame capture quality or playback timing. The full lyrics-only and media runs also include them.

Optionally set `CLEARCAST_UI_LYRICS_FIXTURE` to an absolute local LRCLIB JSON file in the same lyrics-only mode. This exercises actual-song synced lyrics with playback, synthetic project artwork, resizes, replacement/GC and rapid replacements before yielding a frame. Keep song content and dumps under `.runtime/`. The launching process must wait and verify exit code zero as well as the JSON assertions: a deferred native frame-commit failure can occur after the in-app report is written.

In lyrics-only mode, `CLEARCAST_UI_LYRICS_STRESS=lyrics`, `artwork` or `both` isolates 80 frequent track changes with offline delayed/canceled responses, synced/plain/missing lyrics, cover replacements and forced GC. Lyrics modes also replace/collect 30 lyric sets in one dispatcher turn before the next frame; artwork modes cover minimize/restore. Every phase is recorded in JSONL and a latest checkpoint so a native crash can be located even without a final report. `CLEARCAST_UI_LYRICS_STRESS=backpressure` reuses the existing rendering and artwork queue checks without starting a receiver. The local crash watcher under `.runtime/qa-lyrics-review/` can capture full dumps of only this marked test process; it is a debugging artifact, not an application or system configuration change.

`CLEARCAST_UI_LYRICS_STRESS=audit` checks range changes while a seek control is paused, floods native input with 5,000 callbacks, and switches tracks 1,000 times while an HTTP handler deliberately delays cancellation. It verifies the input limit, stale callback revocation, one active lyrics request plus the newest pending track, and shutdown cleanup. This mode also uses disposable state and no receiver ports. UI-test builds carry a `+ui-tests` informational version and are rejected by release packaging.

`CLEARCAST_UI_LYRICS_STRESS=performance` measures 80/400/2000 synthetic lyric rows through automatic, wheel and touch scrolling. It records UI callback timing, allocations, geometry updates and animation submissions in `lyrics-performance.json`, and verifies bounded visible work, unchanged emphasis, high contrast and re-entering rows. `CLEARCAST_UI_LYRICS_PERF_BASELINE=1` records the same workload without the optimized-work assertions. Use distinct marked test homes for before/after runs. These measurements describe UI/Composition submission cost, not GPU presentation FPS.

`CLEARCAST_UI_LYRICS_STRESS=input` checks the published Composition position for precise deltas, reversals, no trailing offset tween, zero-net browsing, playback changes during a manual hold, ongoing gestures, release/expiry, bounds and plain lyrics. It writes `lyrics-input.jsonl` and `lyrics-input-results.json`. This checks the actual shared input method and submitted visual state; it does not measure physical device latency or prove continuity when interrupting an automatic animation.

`CLEARCAST_UI_LYRICS_STRESS=fullscreen` isolates three music full-screen enter/exit cycles without rendered lyrics or artwork. The native debugger's extra heap checks can trigger a separate WinUI titlebar failure on this machine; compare with a normal process launch and, when retaining debugger capture, `_NO_DEBUG_HEAP=1`. Keep that instrumented failure distinct from normal-runtime results. Details and exact stacks are in `.runtime/qa-lyrics-review/QA-summary.md`; the product's full-screen implementation was not changed for that debugging condition. The UI harness drains the background's async disposal before posting `WM_CLOSE` to its owned window, and records the external process exit as a separate requirement.

Set `CLEARCAST_UI_DIAGNOSTICS_ONLY=1` to run the focused F12 checks. They exercise first-press/repeat handling on the owned native video HWND and a focused WinUI music control, source/rendered frame-rate separation, dropped-frame counters and resets, and music placement above artwork. Video placement assertions independently measure the owned HWND and fitted source image: windowed landscape, portrait, rotation and clipped native-size video keep the panel flush within the visible picture; full screen uses a 16-DIP screen inset, including native-size video smaller than the screen. Probes verify the owned layered window, position, click-through styles, visibility, and actual premultiplied pixels with translucent background and transparent corners; the native video remains intact beneath it. The normal harness also includes them. `MediaDiagnosticsTests.cs` covers bounded optional JSON fields, duplicate/non-finite/range rejection, compatibility with older snapshots and localized omission of unknown values. Native CTest `media_diagnostics_source_caps` verifies source caps before scaling/resampling and stream-scoped bitrate tags; the authenticated direct-video protocol fixture checks actual MP4/HLS metadata, source replacement and stop/EOS cleanup.

The same focused harness rasterizes both skip icons at native DPI on their original 24×24-DIP canvases. It records their ink bounds and verifies transparent outer padding plus nonempty arrow and digit regions, guarding against clipping the source geometry in a smaller container. The isolated transparent PNGs are saved with the button names.

`CLEARCAST_UI_BACKPRESSURE_ONLY=1` runs stopped-receiver rendering/artwork tests with blocked consumers and bursts of 5000 updates. It checks one active operation plus the latest pending input, the global four-worker SVG limit, immediate clear, disposal, obsolete HWND callbacks and coalesced geometry. Network tests cover concurrent notifications, valid-interface retention, stale probes, transient and exceptional probes, confirmed failure and no-adapter recovery through test-only delegates; they never change the OS network configuration. It also tests oversized pairing-list failure without partial rows, the existing confirmed-clear recovery action, busy guards and valid-file recovery. The normal harness includes these after its independent startup measurements. Diagnostics-only checks additionally force a real raster failure, prevent an immediate retry storm and recover the unchanged panel after the retry interval. See [reliability and security](RELIABILITY_SECURITY.md) for the production policies.

It also focuses the rotation, full-screen and disconnect buttons during synthetic mirroring, posts Space down/repeat/up only to the application's owned focus HWND, and verifies that no default click, rotation, presenter change or disconnect occurs.

For a startup/close lifecycle smoke test, run:

```powershell
python tests/ui/ui_lifecycle_smoke.py --app .runtime/app-ui/ClearCast.exe --output .runtime/qa-ui-lifecycle/results.json
```

Ordinary XAML captures use `RenderTargetBitmap` with an opaque theme background; they exclude the DWM/Mica backdrop, hand-in Composition visuals, and native video surfaces. Synthetic player tests exercise the application's own HWND geometry, clipping, full-screen presenter and Escape handler. They do not establish decoded video quality, audio synchronization, frame rotation or orientation changes on physical devices.

## Music compositor capture

The same UI harness automatically invokes `MainWindow.CompositorUiTests.cs` during the 1120-pixel music layouts in the controlled light and dark themes, and on Settings and About in dark English mode; no separate launch flag is needed. It uses `PrintWindow(PW_RENDERFULLCONTENT=2)` only on the test process's own HWND, verifies ownership before each capture, and compares two frames two seconds apart while page text and the window caption remain fixed. It checks 32 warped and blurred artwork textures and 33 layers with at most two visible at a time. The flow retains its original 34 channels: 33 opacity expressions plus one shared phase clock, controlled by one rate controller. Two persistent background scale/offset expressions bring normal motion to 36 channels; a finite strong-beat scalar animation temporarily brings it to 37. The harness records color-change measurements outside the current page's static content as well as over the whole window.

The media UI checks also read the real controller's playback rate and progress, exercise smooth density changes without restarting animations, and verify pause, missing artwork, stale samples and session resets. System motion, visibility and high-contrast gates remain authoritative. The texture construction, source attribution and PCM boundaries are documented in [Music background](MUSIC_BACKGROUND.md); rendered-frame evidence and pure state assertions establish different parts of the behavior.

`MainWindow.BeatUiTests.cs` adds strong-beat checks through the real host and Composition control in both light and dark themes. With the flow clock held still, it captures the baseline, attack, rebound, and settled background while checking that foreground artwork pixels and layout bounds remain unchanged. The artwork ROI uses the actual image rectangle with zero extra padding and a DPI-aware inner inset. It checks one impulse per accepted event, weak/stale/duplicate/older-epoch rejection, a parsed invalid-sample FLUSH generation, motion-policy resets, and a new beat arriving during the previous tail without flipping the offset direction. The 360 ms impulse uses a precomputed sampled damping curve, a 1.05 baseline, a maximum scale of 1.17, an approximately 1.0336 minimum at full rebound, and an offset capped at 0.8% of the corresponding viewport dimension or 10 logical pixels. Settled captures wait for the configured duration plus a margin. API fallback can disable the extra beat channels while preserving the original flow.

Pure pulse tests cover normalized peaks, decaying rebound, soft/strong strength mapping, timing gates, and viewport coverage across the sampled curve. Parser tests check age attenuation; host/control checks exercise a new beat during the prior tail. Artwork tests cover the stronger light-theme color treatment and its minimum-brightness guard; dark-theme rendering retains its previous processing. Test results and rendered comparisons belong in the ignored QA directory, not this guide.

The same test entry exercises the real isolated receiver's 50 ms activity-only poller: it temporarily stops the 150 ms metadata timer, waits for asynchronous artwork setup, observes repeated native reads without applying idle metadata to the synthetic music page, and checks timer stop/resume. Fast polling is enabled only while the music background can animate; metadata and progress retain their normal cadence. These checks prove host routing and visual behavior. Synthetic host events do not prove PCM beat detection or acoustic synchronization; native PCM and actual codec fixtures cover the signal path separately.

When capture returns visible content, images use the `*-music-window-1.png` and `*-music-window-2.png` names under `ui-test-output/`. The `layouts` entries in `results.json` identify the capture method, animation state, geometry, changed-pixel measurements, and capture status. `PrintWindow` can omit or freeze WinUI Composition visuals; blank or insufficiently changing output is recorded as `unsupported` with a reason, separately from the XAML, palette, and animation-lifecycle assertions. Do not treat that status as proof of a playback failure or as captured compositor-motion evidence. System animation preferences and high-contrast behavior are exercised separately.

## Original music screenshots

For release screenshot preparation, set `CLEARCAST_UI_STORE_ARTWORK` to the absolute path of a bounded original PNG before running the same isolated UI harness. This optional path is implemented only in `MainWindow.StoreUiTests.cs`, which is excluded from normal builds. Keep its source artwork, generator and provenance in the ignored QA directory; do not use private or third-party album covers.

The harness temporarily suspends metadata polling while its isolated receiver remains alive, applies fictional track information and a generic `ClearCast PC` receiver name, and captures the application's own window through the same compositor capture path. It captures music and the waiting page at 1920 × 1080 and Settings at 2560 × 1440 so the settings cards fit. Chinese screenshots use `zh-CN`; other Store languages can use the English `en-US` images. Light and dark captures are saved without image edits to `ui-test-output/store-music/`, with source and screenshot hashes in `provenance.json`. Set `CLEARCAST_UI_STORE_ONLY=1` for the capture workflow alone. Unsupported sender controls remain hidden. The fixtures do not send remote playback commands or establish compatibility with a physical music player. Preferences, media state, window placement, receiver display name and polling are restored afterward.

`direct_video_app_test.py` can also use `--source-video` with an owned 1280 × 720 demonstration MP4, `--language zh-CN|en-US`, `--theme system|light|dark`, and `--store-screenshots` with `--desktop-controls`. The existing authenticated playback checks save unedited owned-window video captures, with the same process-path guard used for control tests. Capture runs must be serialized with other native window or Sandbox interaction tests to avoid foreground contention; the input guard fails rather than typing into another window.

The desktop control probe also toggles F12 twice during actual decoded windowed/full-screen playback and reads the displayed source geometry, codec, source frame rate and rendered frame rate through UI Automation. It measures placement against the actual video in a window and against screen bounds in full screen, checks the layered surface above intact video, captures the owned window while information is visible, and leaves it hidden afterward. Store capture-only mode skips this action. Playback starts with `/play` alone, so an extra `/rate=1` cannot conceal startup regressions. The native protocol fixture additionally delays media bytes, verifies readiness before preroll, preserves a loading-time pause, explicitly resumes, and verifies that a later new `/play` starts automatically. It protects the compatible HTTP capability mask and separately compares RTSP and TXT values.

The relative-skip protocol checks use a 60-second MP4 with sparse, irregular keyframes. From a paused 7.25-second non-keyframe position they check accurate ±10-second movement and unchanged pause state, burst accumulation without a client snapshot refresh, replacement by absolute seek or HTTP scrub, and skips from the current clock after playback advances. They also cover exact signed-offset validation, current-session ownership, live-stream rejection and seek-range bounds. The desktop probe checks paused non-keyframe skips and advancing playback through the actual buttons. Its focused-button Space probe uses UI Automation to focus each rotation, full-screen and disconnect action, then posts down/repeat/up to the owned focus HWND and verifies a single playback toggle with unchanged player geometry and visibility.

Use `--desktop-controls --no-global-input` when the desktop may have other foreground activity. This retains process-owned UI Automation, relative-skip buttons, focused-button Space down/repeat/up probes, F12/native Space messages and captures, and records Home, mouse-drag and global XAML Space checks as skipped; accessible seek replaces Home. Focus HWND ownership is checked before posting messages. The default full-input mode and its foreground ownership guard remain available. A foreground guard failure is not a playback result, and no test may send input to a different application.

## Software decoder smoke

With 64-bit Python and FFmpeg containing the `libx264` and `libx265` encoders:

```powershell
python tests/media/media_decode_smoke.py --runtime .runtime/receiver --ffmpeg C:/path/to/ffmpeg.exe --output .runtime/qa-media-results.json
```

This loads only the supplied runtime's core/typefind, video parser and libav plugins. It generates twelve 320×180 frames for each codec, checks parser and software-decoder output dimensions, raw buffer size, changing pixel hashes and EOS, then deletes its temporary clips and registry. The JSON records actual component versions and hashes. It uses `fakesink`: no receiver ports, hardware decoder, device video sink or audio output are opened. This smoke test does not replace real AirPlay or hardware/media-quality acceptance.

See [native receiver tests](testing-native.md) and [packaging checks](packaging.md) for the other test groups.
